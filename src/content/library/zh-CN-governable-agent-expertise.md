一位资深专家的价值，不只在于记住了多少资料，还在于知道哪些条件重要、什么时候需要更多证据，以及什么情况下应当否定自己的初步判断。企业希望 Agent 复用这类经验，需要同时组织知识、方法和判断边界。

把文档放入知识库是一个起点。能够检索到内容，只说明材料可访问；任务中怎样使用、结果怎样验证、方法变化后如何控制影响，还需要明确设计。

## 把知识组织成有条件的方法

以可靠性评估为例，“检查重试风险”只是一条提醒。可执行的方法还要定义检查哪些调用边界、需要哪个版本的配置、怎样关联同一业务操作、哪些证据支持调用放大，以及哪些证据才能支持业务效果重复。

一个可维护的方法单元应包含目标、适用前提、输入、执行步骤、判据、反例和来源。遇到未知状态时怎样处理，也属于方法。这样，Agent 可以沿着专业约束工作，而不是从一段经验描述中自行补齐规则。

既有工程文章和专业报告能提供方法结构，但换到另一行业时仍需重新确认语义。资金核对规则不能直接拿来判断采购审批是否合理。

## 版本绑定任务，变化才有解释

知识可以采用人能够阅读和比较的格式维护，例如 Markdown；任务状态、工具执行和证据索引则有各自的记录职责。关键是知道每项任务实际采用了哪一版方法。

对正在执行的任务，不应因为知识文件被编辑就悄悄改变规则。新内容先成为候选版本；已有任务继续使用原版本，或在明确记录的条件下迁移。若两个任务给出不同结论，版本记录能够帮助区分材料变化、方法变化和执行差异。

这种设计也让专家能够审阅改动：新增了什么检查，删除了什么条件，是否改变失败与未知状态的处理。

## 用评测证明变化有效

评测任务要覆盖正常输入、已知问题、资料缺失、容易误判的反例，以及工具不可用时的行为。候选版本和当前版本在可比较条件下执行，保留实际输出、验证依据、人工复核和总投入。

“多读了几份文档”不能直接作为能力升级依据。一个角色在一项任务上改善，也不能证明其他角色或领域都已提升。独立核验者需要检查方法是否真的提高了判断质量，是否引入新遗漏，以及额外成本是否值得。

评测结果可以是采用、继续修订或保留旧版。撤回时要明确影响的是后续方法选择；已经发生的业务操作不会因为恢复旧知识文件而自动撤销。

## 能力档案应指向证据

企业可以按领域知识、分析判断、执行交付、质量与风险、协作表达组织角色能力档案。维度的意义是帮助找出短板，而不是制造一个看似精确的总分。

每项评价附适用任务、证据、日期和待补能力。没有评测就保留待评估；“专家”之类称谓也需要说明适用范围。定期复核优先检查知识与工具是否变化、已有证据是否仍适用，再决定需要哪些新的学习与验证。

## 从已有工程积累开始

Smartscity 的可靠性评估方法已经按检查对象、证据与结论组织内容，报告区分总体判断和逐项依据。这种专业积累可以支撑 Agent 方法设计；报告模板本身不能证明 Agent 已具备对应诊断能力。

当前智能体项目已开展本地角色学习与方法比较探索。现有记录中，部分方法升级有比较依据；角色扩展、知识版本管理与能力评估还在建设。企业采用时仍需围绕自己的任务建立证据，不把本地探索当成成熟治理产品。

适合启动的试点，是企业有反复执行的专业任务、能够提供方法来源，并有专家愿意定义验收。例如，选择一类变更评估，把当前方法固化为基线，再比较一次候选改进的有效性和维护成本。
