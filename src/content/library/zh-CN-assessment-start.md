## 明确一个业务问题

说明业务操作、涉及的系统、近期或计划中的变更，以及需要作出的决策。明确能够解释业务语义的人员和各系统负责人。限定环境与版本窗口，避免混用不兼容快照的证据。

## 准备材料清单

| 输入           | 有用的细节                             |
| -------------- | -------------------------------------- |
| 业务约束       | 预期终态、不可接受的重复或遗漏         |
| 架构           | 调用路径、依赖、归属与故障域           |
| 配置与变更记录 | 版本、重试与超时、迁移与发布计划       |
| 运行证据       | 脱敏调用链、事故时间线、相关指标与日志 |
| 验证条件       | 可用隔离环境、允许的故障、停止条件     |

先提供清单，不直接开放无限制访问。初次邮件不要包含凭证、个人数据或机密日志。敏感材料的交换方式和访问范围需要另行约定。

## 发送有范围的需求

使用下方邮件入口，在邮件应用中打开预填的本页标题与 URL；发送前可以修改内容。网站不提交表单，也不保存请求。请补充问题概述、首选联系方式与时间约束。例如：

```text
业务问题：回滚后旧版本能否继续处理订单？
范围：订单服务与消息消费者；预发环境。
已有材料：发布差异、迁移计划、脱敏调用链。
验证边界：与系统负责人共同约定。
联系人与期望时间：[填写你的信息]
```

## 验证前确认合作边界
